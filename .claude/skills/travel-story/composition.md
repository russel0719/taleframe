# 구성 규칙 — 아웃라인, 템플릿, 리듬

## 아웃라인

기본 뼈대는 제안일 뿐이다. 여행마다 챕터 수·순서·테마가 달라야 한다.

1. 오프닝 — 여행의 분위기를 한 번에 (대표 컷 / 지구본 / 엽서)
2. 여정의 시작 — 도착과 첫인상
3. 여행의 리듬 — 이동, 산책, 거리
4. 주요 테마 — 미식 · 자연 · 문화 중 이 여행의 중심
5. 하이라이트 — 사용자가 꼽은 가장 기억에 남는 순간
6. 에필로그 — 회고 문장과 마지막 장면

- **날짜 기준 vs 테마 기준**을 먼저 정한다. 일정이 이야기면 날짜(Day 1, 2…), 음식이 이야기면 테마 챕터.
- **미디어가 부족한 챕터를 만들지 않는다.** 사진 2장으로 챕터를 세우지 말고 이웃 챕터에 합친다.
- **분량**은 ② 웹 방향의 답을 따른다 — 짧게 10~14 · 보통 16~22 · 길게 24~32 섹션.
  길게 할 때는 섹션을 늘리기 전에 **쓰지 않은 사진**부터 본다 (analysis 의 score 3 이상 중 미사용).
  같은 사진을 두 섹션에 쓰는 건 지도 카드(map-journey stops)와 타임라인 썸네일만 허용한다.
- 챕터가 3개 이하면 chapter-divider 를 쓰지 않는다.
- 아웃라인 표: `챕터 | 핵심 내용 | 쓸 미디어 id | 근거(사용자 답 / 사진)`.

## 기록과 작품

섹션은 두 종류다. **기록**은 무슨 일이 있었는지 전하고(사진+자막, 음식, 지도, 타임라인),
**작품**은 장면 하나를 작품처럼 보여준다(카탈로그에서 category 가 `art` 인 9종). 작품만 있으면 전시 도록이 되고,
기록만 있으면 블로그가 된다. 이 사이트가 노리는 건 그 사이다.

- 작품 섹션은 **연달아 두지 않는다** (validate 가 경고). 기록 섹션 1~3개마다 하나가 적당하다.
- 개수는 ② 웹 방향의 "작품 비중"을 따른다. 같은 작품 템플릿은 한 스토리에 한 번이 원칙 (film-roll·verse 는 두 번까지).
- 자리:
  - **장의 문** — kinetic-type (도시 이름) 이나 chapter-divider 대신 쓰면 장이 극적으로 열린다
  - **장 사이의 숨** — verse, color-field
  - **하이라이트 직후의 여운** — diptych, spotlight
  - **시간이 흐른 묶음** — film-roll (한나절·하룻밤의 연속 스냅 4~12장)
  - **유쾌한 한 컷** — riso-print (형태가 뚜렷한 간판·음식)
  - **에필로그** — palette-diary (날마다 한 줄)
  - **많이 걸은 날의 끝** — walk-line (그날 map-journey 와 같은 장소면 둘 중 하나만)
- 고르는 기준:
  - verse: 고요한 장면 (신사, 눈, 강). 사람 많은 사진은 피한다
  - color-field: 색이 서로 다른 사진 2~5장 (같은 주홍만 셋이면 변화가 안 느껴진다). 생성 후 shot 에서 배경색을 확인
  - spotlight: 밤·네온·등불. 낮 풍경 금지
  - diptych: 구도가 좋은 2~3장, 제목을 붙일 수 있어야 한다
  - riso-print: 얼굴이 크게 나온 사진 금지. 사진 팔레트가 탁하면 `inks` 를 직접 지정 (형광 핑크 `#ff48b0` + 블루 `#3255a4` 가 기본)
  - kinetic-type: 6자 이하. 사진은 색이 강하고 전체가 고르게 찬 컷 (글자 속에 비친다)
  - palette-diary: 날마다 그날 사진 전부(최대 48장)를 넣어도 된다 — 많을수록 색의 흐름이 보인다
  - walk-line: 걸어서(walk) 이은 구간이 있어야 선이 그려진다. 쓴 뒤 `tf routes` 를 돌린다 (map-journey 와 같은 규칙: transport 는 사용자 답에서, 숙소 좌표 금지)

기록물(기록 섹션이지만 손에 쥐는 물건처럼 보인다):
  - stamp-rally: 가게 `name` 은 사용자가 말한 것만. 모르면 비워 둔다(빈 도장 "?"). 같은 종류 가게 3곳 이상일 때
  - transit-ticket: from·to·mode 는 사용자 답에서. 시각(depart·arrive)·운항사는 확인된 것만 — 없으면 뺀다
  - day-clock: 그날 사진 3~12장, 이른 아침~밤으로 퍼져 있을 때. `place` 는 도시 단위 좌표(숙소 금지)
  - contact-sheet: 같은 자리에서 연달아 찍은 6~24장. 사용자가 고른 컷(또는 하이라이트로 답한 컷)에 `pick`
  - photo-map: `points` 좌표는 inventory GPS 를 **소수점 3자리로 반올림**(스키마가 강제). 숙소 반경 사진은 넣지 않는다
  - postcard-back: `message` 는 **사용자가 쓴 한마디만** (② 웹 방향이나 ⑤ 보완 질문에서 "누구에게 무슨 말을?" 으로 받는다). 없으면 고르지 않는다
  - receipt: 날마다 하나. 항목 이름은 확인된 것(사용자 답·사진 속 간판)만, `price` 는 사용자가 말한 것만 — 없으면 "—" 로 둔다. 시각은 비우면 사진 촬영 시각
  - split-flap: 오프닝이나 도시가 바뀌는 챕터의 문. 글자는 지명·날짜처럼 확인된 것만, 줄마다 16자 이내 (한 줄에 영문 9~10자가 보기 좋다)
  - photo-stack: 폰에서 넘겨 보는 스냅 3~12장. 사람·일행 사진에 잘 맞는다. 캡션은 짧게(손글씨로 보인다)
  - scrap-object: 표·입장권·영수증·지도처럼 **실물을 찍은 사진**만. 이름·카드번호·QR 이 보이는 실물은 쓰지 않는다 (공개 사이트)

## 템플릿 고르기

`npm run tf -- catalog` 의 "어울림/피함"을 기준으로, 섹션마다 1~3개 후보를 놓고 고른다. 배치표:

`# | 섹션 id | 기록/작품 | 템플릿 | 미디어 | 왜 이 템플릿인가 | 대안 | 부족한 정보`

판단 순서:
1. **필수 조건** — 필요한 미디어/필드가 있는가. 없으면 후보에서 뺀다
   - map-journey: 서로 다른 장소 2곳 이상 + 확인된 이름 + 공개해도 되는 좌표
   - weather-card: 확정된 날짜와 도시 (좌표는 도시 중심이면 충분)
   - panorama: 2:1 equirectangular 사진만 (일반 가로 파노라마는 photo-single size=full)
   - before-after: 같은 구도의 두 장
   - scroll-scrub: 카메라가 한 방향으로 움직이는 클립
   - food-review / editorial-text / quote-moment / travel-stats: 사용자에게 받은 문구·숫자가 있어야 한다
2. **내용 적합성** — 섹션의 목적(풍경·음식·회고·이동)과 맞는가
3. **미디어 적합성** — 세로 사진은 photo-single(narrow)·polaroid·split, 가로는 overlay·hero. 영상 길이와 소리
4. **사용자 취향** — ② 웹 방향의 톤. 차분함 → sticky-story·quote·photo-single / 유쾌함 → polaroid·postcard·photo-strip
5. **리듬과 다양성** — 아래 규칙

## 리듬

- **같은 템플릿을 연달아 쓰지 않는다** (의도가 있으면 memo 에 이유를 적는다). validate 가 경고한다.
- **긴 스크롤 장면**(sticky-story · scroll-scrub · map-journey)은 붙여 놓지 않는다. 사이에 짧은 섹션을 둔다.
- **강약을 번갈아**: 시네마틱(hero · overlay · video · scrub) 뒤에는 조용한 섹션(photo-single · editorial · quote · fact).
- **영상은 흩어 놓는다.** 몰아 두면 따로 노는 영상 두 편처럼 보인다.
- 모든 섹션을 같은 크기의 카드로 만들지 않는다. 화면 가득 → 좁은 단일 사진 → 묶음 갤러리처럼 스케일을 바꾼다.
- 다양성을 위해 이야기에 맞지 않는 템플릿을 억지로 넣지 않는다. 지도·음식·통계는 없어도 된다.
- 섹션 수는 분량 답을 따른다. 사진을 다 쓸 필요는 없다 — 고르는 게 편집이다.
- 막(幕) 구조: **프롤로그**(hero/globe/postcard) → 장마다 **문**(chapter-divider 또는 kinetic-type) → 기록과 작품을 번갈아 →
  **에필로그**(closing). 긴 스토리는 장 사이에 작품 하나로 숨을 쉬게 한다.

## 톤 (배경)

템플릿마다 기본 톤이 있고, 같은 톤이 연달아 오면 렌더러가 자동으로 한 단계 바꾼다.
`tone` 은 특별한 이유가 있을 때만 직접 지정한다 (예: 밤 장면 묶음을 전부 dark 로).

## 커버와 제목

- `cover`: 목록 카드와 공유 이미지에 쓰인다. 가로 사진, 피사체가 가운데 근처, 문구 없이도 여행이 읽히는 컷.
- `title` 은 짧게 (공유 카드에 한 줄로). 사용자에게 2~3개 후보 + Other 로 묻는다.
- `summary` 는 목록 카드의 한두 문장. 사용자가 한 말에서 만든다.
