# 인터뷰 규칙

`AskUserQuestion` 으로 묻는다. **한 번에 4문항까지.** 각 문항은 2~4개 선택지 + 사용자가 직접 쓰는 Other.
사용자가 Other 로 자기 말을 쓰는 게 가장 좋은 결과다 — 선택지는 그걸 끌어내는 마중물이다.

## 공통 원칙

- **이미 아는 것은 묻지 않는다.** EXIF 날짜, 사용자가 대화에서 이미 말한 것, interview.json 에 있는 것.
- **선택지는 증거에서 만든다.** 사진 장면, places.json 후보, 시각. 증거가 없으면 열린 질문으로 묻는다.
- **질문에 그 컷이 어떤 장면인지 글로 적는다** (`m023 — 해 질 녘 강변, 네온 간판`). 사용자는 썸네일을 못 본다.
- **짐작은 짐작으로.** "후시미 이나리 같은데 맞나요?" (O) / "후시미 이나리에서" (X — 확인 전에 문구에 넣지 않는다)
- 모든 문구 질문에 **"자막 없이"** 선택지를 넣는다. 사진만으로 충분한 컷이 많다.
- 감정·의미를 지어내 선택지로 내밀지 않는다. ("설렘 가득한 첫날" 같은 선택지 금지)
  대신 "이 장면이 여행에서 어떤 의미였나요?" 처럼 열어 두고, 선택지는 사실/톤 위주로.
- 사용자가 "모르겠다/건너뛰기" 하면 그 항목은 비운다. 다시 조르지 않는다.
- 받은 답은 즉시 `work/<slug>/interview.json` 에 `{ "q": "...", "a": "...", "at": "섹션 또는 항목" }` 로 덧붙인다.

## 라운드 1 — 여행 자체 (사진만으로 알 수 없는 것)

보통 이 4개:

1. **어디·언제** — "오사카·교토, 2026년 2월 6~9일로 보이는데 맞나요?" (EXIF·GPS 근거를 질문에 적는다)
2. **여행의 성격** — 휴식 / 미식 / 문화·관광 / 특별한 일 … 사진 분포에서 2~3개 골라 제시 (multiSelect)
3. **톤** — 차분하고 시네마틱 / 담백한 기록 / 유쾌하게 / 일기처럼. 톤이 템플릿 선택(폴라로이드 vs 스크럽 영상)을 가른다
4. **사람이 나온 사진** — 공개 사이트임을 알리고: 일행 얼굴 포함해도 됨 / 뒷모습·작게만 / 사람 컷은 빼기

## 라운드 1.5 — 만듦새 (한 번만 묻고 interview.json 에 남긴다)

5. **분량** — 짧게(섹션 10~14, 사진 15장 안팎) / 보통(16~22, 25장) / 길게(24~32, 35장+). 사진 수로 현실적인 선택지만 낸다
6. **작품 섹션의 비중** — 기록 위주(작품 섹션 1~2개) / 섞어서(3~5개) / 전시처럼(6개 이상, 장마다 하나)
7. **AI 문장** — 안 씀(사용자 문장만, 나머지는 자막 없이) / 사실형 초안만 제안 / 작품 섹션(시·전시 서문)은 AI 가 써도 됨
   → 고른 답이 이후 모든 문구 라운드의 기본값이다. 매번 다시 묻지 않는다.

지난 작업에서 사용자가 문구 라운드 도중 "감성 문구 하나 적어줘"라고 두 번 요청했다 — 7번을 처음에 물으면 그 왕복이 없어진다.

## 라운드 2 — 이야기의 뼈대

장소명을 확인할 때 **이동 수단도 같이 묻는다** (지도에 실제 길로 그리려면 구간마다 transport 가 필요하다).
"직선 점선"은 사용자가 싫어했다 — 지도 섹션을 넣을 계획이면 이 라운드에서 끝낸다.

- **가장 기억에 남는 순간** — 점수 높은 장면 3개를 짧게 설명해 선택지로. Other 로 쓰게 유도
- **꼭 넣을 것 / 빼고 싶은 것** — 장소·음식·사람. exclude 후보(렌더된 영상, 중복)도 여기서 확인
- **동행** — 혼자 / 연인·배우자 / 친구 / 가족 (어투가 달라진다. 이름은 묻지 않는다)
- **문구 말투** — 짧은 시적 문장 / 사실 위주 / 일기체(~했다) / 대화체

## 라운드 3 — 구조 승인

composition.md 에 따라 아웃라인 표를 텍스트로 먼저 보여주고, 질문은 "이 순서로 갈까요?"
선택지: 좋다 / 챕터를 줄이자 / 순서를 바꾸자 / (Other 로 구체 수정).
템플릿 배치표도 같은 방식으로.

## 문구 라운드 — 섹션마다 한 문항

문구가 들어가는 섹션만 묻는다. 섹션 수가 많으면 여러 라운드가 된다 — **길다고 건너뛰지 마라.**
지루해 보이면 문구가 꼭 필요한 섹션만 남기고 나머지는 "자막 없이"로 정해 문항 수를 줄인다.

문항 형식:
- 질문: `[섹션 id · 템플릿] m031 — 좁은 골목, 붉은 등이 늘어선 저녁. 이 컷의 문구는?`
- 선택지: ① 사실형 초안 (확인된 사실만: "기온 거리, 저녁") ② 사용자가 앞서 한 말을 다듬은 것 (있을 때만)
  ③ "자막 없이" ④ (Other)
- 음식: 메뉴명·가게 이름·가격은 **각각 확인된 것만**. 모르면 그 필드는 비운다. "가게 이름 기억하세요?"를 따로 묻는 건 괜찮다.
- 장소명: places.json 후보를 선택지로 쓰되 "다른 곳 / 모름"을 반드시 넣는다.
- 숫자(travel-stats, fact-card): 사용자가 말한 숫자만. "걸음 수 기록 있으세요?" 없으면 그 항목 제외.

## 답이 일부만 왔을 때

Other 로 일부만 답하는 경우가 있다 (예: 3단계 문장 중 셋째만). 나머지를 초안으로 조용히 채우지 말고,
**다음 라운드에서 빠진 부분만 다시 묻는다** — "①② 단계는 비워 둘까요, 사실형 초안을 쓸까요?"
작품 섹션처럼 문장이 필수인 곳이면 선택지에 "섹션을 다른 템플릿으로 바꾸기"를 넣는다.

## 작품 섹션의 문구

- verse: 줄당 24자 이내, 1~8줄. 사용자의 메모가 있으면 그것을 행갈이만 해서 쓰는 게 최선이다.
  AI 문장을 허락받았다면 장면에 **보이는 것과 사용자가 말한 것만** 재료로 쓴다 (없던 감정·사건 금지).
- diptych: 작품 제목은 장소명이나 사진에 보이는 것 ("기요미즈데라, 오후 한 시"). 서문(statement)은 사용자 말에서.
- kinetic-type: 6자 이내 한 단어 — 도시 이름, 챕터의 핵심어. 사실이므로 따로 묻지 않아도 된다.
- film-roll label: 영문 대문자 ("KYOTO 2026"). 사실이므로 묻지 않는다.
- color-field·spotlight·riso-print 캡션은 선택 — 기본은 비운다.

## 하지 말 것

- 한 문항에 두 가지를 묻기 ("어디였고 기분은 어땠나요?")
- 사용자의 답을 다듬으면서 의미를 바꾸기 — 다듬은 문장은 다시 확인받는다
- 질문 없이 그럴듯한 문구로 빈칸 채우기
