# 인터뷰 규칙 — 다섯 단계

**① 사진 질문 → ② 웹 방향 → ③ 레이아웃 승인 → ④ 초안 확인 → ⑤ 보완 질문** (④⑤를 반복) → 게시.

문구를 전부 받은 뒤에 페이지를 쓰지 않는다. **사진과 방향만 정해지면 빈칸이 있는 초안을 먼저 보여주고**,
초안에서 비어 있거나 확인이 필요한 곳만 골라 다시 묻는다. 사용자는 결과를 일찍 보고, 질문은 꼭 필요한 것만 받는다.

한 번에 4문항까지. 각 문항은 2~4개 선택지 + 사용자가 직접 쓰는 답(대화형 스킬은 Other, Studio 는 "직접 쓰기" 칸).
사용자가 자기 말로 쓰는 게 가장 좋은 결과다 — 선택지는 그걸 끌어내는 마중물이다.

## 공통 원칙

- **이미 아는 것은 묻지 않는다.** EXIF 날짜, 사용자가 이미 말한 것, interview.json 에 있는 것.
- **선택지는 증거에서 만든다.** 사진 장면, plan-matches.json(사용자의 계획), places.json 후보, 시각. 증거가 없으면 열린 질문으로 묻는다.
- **질문마다 관련 사진을 붙인다.** Studio 는 질문의 `media` 에 사진 id 1~4개를 넣으면 폰에 사진이 함께 보인다 — 장면 설명은 짧게.
  대화형 스킬은 사진을 못 보여주므로 장면을 글로 적는다 (`m023 — 해 질 녘 강변, 네온 간판`).
- **짐작은 짐작으로.** "후시미 이나리 같은데 맞나요?" (O) / "후시미 이나리에서" (X — 확인 전에 문구에 넣지 않는다)
- 감정·의미를 지어내 선택지로 내밀지 않는다. ("설렘 가득한 첫날" 같은 선택지 금지)
  대신 "이 장면이 여행에서 어떤 의미였나요?" 처럼 열어 두고, 선택지는 사실/톤 위주로.
- 사용자가 "모르겠다/건너뛰기" 하면 그 항목은 비운다. 다시 조르지 않는다.
- 받은 답은 즉시 `work/<slug>/interview.json` 에 `{ "at": "항목", "q": "...", "a": "...", "phase": "photos|direction|layout|gaps" }` 로 덧붙인다.

## ① 사진 질문 — 사진만으로 알 수 없는 사실 (보통 1~2라운드)

사진을 훑어본 결과(analysis.json)와 장소 후보(places.json)를 들고 묻는다. 이 단계에서는 **웹 모양을 묻지 않는다.**

**travel-plan 계획이 있으면(`work/<slug>/plan-matches.json`) 먼저 그것으로 묻는다 — 장소를 하나하나 묻지 않는다.**

1. **일괄 확인 (질문 하나, 첫 라운드)** — `confirm` 목록 전체를 한 번에:
   "여행 계획(travel-plan)과 사진 시각·위치가 맞는 곳이에요. **실제와 다른 곳만** 골라 주세요."
   multiSelect 선택지는 날짜별로 묶은 일정 줄(`10/22 지중 미술관 11:00–12:00 · 사진 12장`)과 "모두 맞다".
   선택지는 5개까지라 일정이 많으면 날짜 단위("10/22 일정 14곳 — 다른 곳 있음")로 묶고, 고른 날만 다음 라운드에서 펼친다.
   고르지 않은 줄은 사실로 확정해 interview.json 에 `{ "at": "plan-confirm", "a": "확인", "items": [일정 id…] }` 로 남긴다.
2. **어긋남 (`ask` 묶음마다 질문 하나)** — "10/23 08:27–08:30 사진 9장: 계획엔 '우동 → 리쓰린 이동'(08:00–08:30)인데
   위치는 '키쿠게츠테이' 근처예요. 어디였나요?" 선택지: 계획 쪽 / 좌표 쪽 / 둘 다 아님. 계획 시각이 이상하면(오전을 20:30 으로) 그 사실도 짚는다.
3. **계획에 없는 사진(`photos` 에 없음)·`day`** 만 아래 일반 질문으로 묻는다.

계획은 사용자가 적은 자료지만 **계획대로 안 간 날은 반드시 있다** — 확인 없이 사실로 쓰지 않는다. 가격은 notes 에 사용자가 적은 것만.

- **어디·언제** — "오사카·교토, 2026년 2월 6~9일로 보이는데 맞나요?" (EXIF·GPS 근거를 질문에 적는다)
- **장소 확인** — places.json 후보를 선택지로 (multiSelect "맞는 것만"). "다른 곳 / 모름" 을 꼭 넣는다
- **이동 수단** — 장소가 여럿이면 구간마다. 지도에 실제 길로 그리려면 필요하다 (모르면 점선 직선 — 사용자가 싫어했다)
- **사람이 나온 사진** — 공개 사이트임을 알리고: 일행 얼굴 포함 / 뒷모습·작게만 / 사람 컷은 빼기
- **빼고 싶은 사진** — analysis 의 exclude 후보(다른 도구의 결과물, 중복, 스크린샷)
- **가장 기억에 남는 장면** — 점수 높은 장면 3~4개를 사진과 함께 선택지로 (multiSelect). 직접 쓰게 유도
- **동행** — 혼자 / 연인·배우자 / 친구 / 가족 (문구의 시점이 달라진다. 이름은 묻지 않는다)

이 단계가 끝나면 장소·날짜·사람·하이라이트가 사실로 정해져 있어야 한다.

## ② 웹 방향 — 어떤 페이지로 만들지 (보통 1~2라운드, 한 번 정하면 다시 묻지 않는다)

- **여행의 성격** — 휴식 / 미식 / 문화·관광 / 특별한 일 … 사진 분포에서 2~3개 (multiSelect)
- **톤** — 차분하고 시네마틱 / 담백한 기록 / 유쾌하게 / 일기처럼. 템플릿 선택(폴라로이드 vs 스크럽 영상)을 가른다
- **분량** — 짧게(섹션 10~14) / 보통(16~22) / 길게(24~32). 사진 수로 현실적인 선택지만 낸다
- **작품 섹션의 비중** — 기록 위주(1~2개) / 섞어서(3~5개) / 전시처럼(6개 이상)
- **AI 문장** — 안 씀(사용자 문장만, 나머지는 비운다) / 사실형 초안만 / 작품 섹션(시·전시 서문)은 AI 가 써도 됨
- **문구 말투** — 짧은 시적 문장 / 사실 위주 / 일기체(~했다) / 대화체

## ③ 레이아웃 — 아웃라인과 배치표 승인

composition.md 로 아웃라인(챕터 흐름)과 섹션별 배치표(기록/작품 · 템플릿 · 사진 · 이유)를 만들어 보여준다.
"이대로 / 이렇게 바꿔 주세요" 로 받는다. 수정 요청이면 반영해 다시 보여준다. **승인 전에는 초안을 쓰지 않는다.**

## ④ 초안 — 빈칸이 있어도 먼저 보여준다

승인된 배치표대로 story.json 을 쓴다 (SKILL.md 6절). 문구는 이렇게 채운다:

- 사용자가 답한 사실과 문장 → 그대로
- 사진에 보이는 사실·확인된 장소명·날짜·시각 → 사실형으로 (예: "기요미즈데라, 오후 한 시")
- AI 문장을 허락받은 범위(②) → 작품 섹션의 시·서문 등
- **그 밖의 감상·이름·가격 같은 모르는 것 → 비운다.** 선택 필드면 넣지 않고, 필수 필드면 사실형으로 쓰고
  섹션에 `"memo": "보완: <무엇이 필요한지>"` 와 `"status": "needs_review"` 를 단다

미리보기를 만들어 사용자에게 보여준다. 사용자는 섹션마다 괜찮다/고쳐 달라를 고른다.

## ⑤ 보완 질문 — 초안을 보고 빈 곳만

초안(story.json)의 `memo: "보완: …"` 섹션, 비어 있는 캡션, 확인 안 된 사실을 보고 **필요한 것만** 묻는다.

- 질문마다 어느 섹션인지 밝힌다 (`header` 에 섹션 이름, `media` 에 그 섹션의 사진)
- 선택지: ① 사실형 문장 ② 사용자가 앞서 한 말을 다듬은 것(있을 때만) ③ "비워 두기" ④ 직접 쓰기
- 음식: 메뉴명·가게 이름·가격은 **각각 확인된 것만**. "가게 이름 기억하세요?" 를 따로 묻는 건 괜찮다
- 숫자(travel-stats, fact-card): 사용자가 말한 숫자만. 없으면 그 항목을 뺀다
- 화면에 크게 보이는 곳(오프닝, 하이라이트, 마무리)부터 묻는다. 사소한 캡션은 "비워 두기"가 기본
- 물을 게 없으면 묻지 않는다 — 사용자가 초안을 승인하면 끝이다

답과 수정 요청을 반영해 초안을 고치고 다시 보여준다 (④). 이 과정을 사용자가 전부 승인할 때까지 반복한다.

## 답이 일부만 왔을 때

일부만 답하는 경우가 있다 (예: 3단계 문장 중 셋째만). 나머지를 초안으로 조용히 채우지 말고,
**다음 보완 질문에서 빠진 부분만 다시 묻는다** — "①② 단계는 비워 둘까요, 사실형으로 둘까요?"
작품 섹션처럼 문장이 필수인 곳이면 선택지에 "섹션을 다른 템플릿으로 바꾸기"를 넣는다.

## 작품 섹션의 문구

- verse: 줄당 24자 이내, 1~8줄. 사용자의 메모가 있으면 그것을 행갈이만 해서 쓰는 게 최선이다.
  AI 문장을 허락받았다면 장면에 **보이는 것과 사용자가 말한 것만** 재료로 쓴다 (없던 감정·사건 금지).
- diptych: 작품 제목은 장소명이나 사진에 보이는 것 ("기요미즈데라, 오후 한 시"). 서문(statement)은 사용자 말에서.
- kinetic-type: 6자 이내 한 단어 — 도시 이름, 챕터의 핵심어. 사실이므로 따로 묻지 않아도 된다.
- film-roll label: 영문 대문자 ("KYOTO 2026"). 사실이므로 묻지 않는다.
- color-field·spotlight·riso-print 캡션은 선택 — 기본은 비운다.

## 하지 말 것

- 한 문항에 두 가지를 묻기 ("어디였고 기분은 어땠나요?")
- 사진 질문 단계에서 웹 모양(톤·분량·템플릿)을 묻기 — 사실이 먼저다
- 사용자의 답을 다듬으면서 의미를 바꾸기 — 다듬은 문장은 다시 확인받는다
- 질문 없이 그럴듯한 문구로 빈칸 채우기
